# Theme — قالب و نسخهٔ Storefront

> قبل از کار روی ThemeConfig، Theme Loader یا تنظیمات ظاهری قالب این فایل را بخوان.

**تسک‌ها** — `P0.2.6`، `P0.3.6`، `P3.2`، `P3.3.9`، `P4.2.11` و `P6.4`. [چک‌لیست پروژه](../../TASKS.md)

## مسئولیت و مرز

Theme قرارداد و نسخهٔ قالب‌ها، انتخاب کامپوننت‌ها و اعمال تنظیمات ظاهری را پوشش می‌دهد. Storefront با یک برنامهٔ Astro، نسخهٔ قالب تعیین‌شده برای Tenant را رندر می‌کند. [Settings](settings.md) مشخصات عمومی فروشگاه را پوشش می‌دهد.

## داده‌ها و عملیات

| بخش | محدودهٔ ثبت‌شده |
| --- | --- |
| داده | `themes` و انتخاب‌ها و تنظیمات قالب در `store_settings` طبق schema |
| قرارداد | `packages/theme-contract` و `ThemeConfig` شامل `id`، `name`، `version` و تنظیمات رنگ، فونت و گردی گوشه |
| پنل | انتخاب قالب و تغییر تنظیمات مجاز همان فروشگاه |
| Storefront | Theme Loader و رندر `minimal`، `classic` یا `luxury` با تنظیمات همان Tenant |

## قواعد اجرایی

- سفارشی‌سازی به مقادیر معتبر تنظیمات و کامپوننت‌های تأییدشده محدود است. کد JS یا Astro دلخواه مشتری اجرا نمی‌شود.
- تنظیمات ظاهری با CSS variables اعمال می‌شوند. انتخاب قالب و تنظیمات از Tenant معتبر می‌آیند.
- افزودن نسخهٔ جدید به‌خودی‌خود نسخهٔ فعال فروشگاه‌های موجود را تغییر نمی‌دهد. قرارداد صفحات Storefront در قالب‌های نسخهٔ اول حفظ می‌شود.
- نمایش دکمهٔ خرید، سبد یا تماس و پیام «تماس برای قیمت» در همهٔ نسخه‌ها از حالت مصوب همان فروشگاه و وضعیت محصول طبق D-31 پیروی می‌کند.

## سناریوهای تست

- دو Tenant با دو قالب یا تنظیم متفاوت، خروجی مربوط به خود را روی دامنهٔ خود دریافت می‌کنند.
- قالب یا تنظیم خارج از مقادیر مجاز طبق قرارداد رد می‌شود و در رندر اجرا نمی‌شود.
- افزودن نسخهٔ جدید، خروجی فروشگاهی را که روی نسخهٔ قبلی است تغییر نمی‌دهد.
- هر سه قالب صفحات اصلی خرید و بررسی SEO فاز راه‌اندازی را پوشش می‌دهند.
- هر سه قالب برای یک فروشگاه تماسی، شمارهٔ عمومی و اقدام تماس درست را نشان می‌دهند. تغییر قالب مجوز خرید را تغییر نمی‌دهد.
