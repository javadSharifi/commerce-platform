# نقشهٔ راه سایت‌ساز روان‌شناس‌ها

فقط تسک‌های `PSY-*` به این محصول تعلق دارند. تسک بعدی از [وضعیت اجرا](PROGRESS.md) پیدا می‌شود. هر تسک کوچک را با سند ماژول، سناریوی پذیرش و پیش‌نیازهایش اجرا کن. پایان فاز یعنی مسیرهای پذیرش فاز در محیط توسعه یا تست تأیید شده‌اند. انتشار واقعی هر نسخه تأیید محیط هدف خودش را دارد. [بریف](PROJECT_BRIEF.md) · [تصمیم‌ها](DECISIONS.md) · [پذیرش](ACCEPTANCE.md)

| فاز | خروجی |
| --- | --- |
| `PSY-0` | زیرساخت، دامنه، پنل، احراز هویت و ایزولاسیون |
| `PSY-1` | نسخهٔ ۱، ثبت‌نام کارگاه حضوری و بلاگ |
| `PSY-2` | نسخهٔ ۲، نوبت‌دهی حضوری |
| `PSY-3` | نسخهٔ ۳، آپلود، فروش و پخش دورهٔ ضبط‌شده |
| `PSY-4` | بهره‌برداری و بهینه‌سازی پس از پایلوت |
| `PSY-5` | سیستم طراحی مشترک (`packages/ui`)، تقویم شمسی استاندارد و موتور چندقالبی |
| `PSY-6` | انتخاب مستقل قالب و پالت، انتشار محدود به حساب مجاز و قالب `mobile-app` |
| `PSY-7` | بازطراحی سایت عمومی بر اساس Stitch و اتصال قالب اختیاری به موتور ظاهر |

[پلتفرم](modules/platform.md) · [نقشهٔ مسیرها](PROJECT_MAP.md)

- [x] PSY-0.2 تدوین `docs/psychology/database.md` برای هسته بر اساس [مدل داده](DATA_MODEL.md). `tenant_id`، شناسه‌های ترکیبی، ترتیب قفل‌ها، زمان UTC و قواعد ریال را ثبت کن. Schema دامنه به‌صورت افزایشی در هر فاز تکمیل می‌شود.
- [x] PSY-0.3 ساخت قرارداد سراسری `/v1`، جداسازی Public/Account/Admin و Callback در OpenAPI و تولید کلاینت typed. خطا، pagination و پاسخ‌های خصوصی را تعریف کن.
- [x] PSY-0.4 ساخت migration نقش‌ها، `tenants`، دامنه‌ها، هویت پنل، عضویت و نشست با RLS و lookup محدود. `up/down/up` را اجرا کن.
- [x] PSY-0.5 ساخت resolver دامنه و `WithTenantTx` با pool و sqlc. دو Host و یک Host تأییدنشده را با نقش واقعی آزمون کن.

- [x] PSY-0.7 ساخت پوستهٔ RTL پنل و سایت، پروفایل مطب و تنظیم لوگو و رنگ یک قالب نسخه‌دار. خروجی عمومی فقط فیلدهای انتشارپذیر را نمایش دهد.
- [x] PSY-0.8 تنظیم `make verify-psychology` برای build/vet/test Go و lint/typecheck/test بسته‌های مرتبط. اجرای CI و fixtureهای A و B را مستند کن.

**پایان فاز** — دو سایت محلی با Host جدا، پنل محافظت‌شده و تست ایزولاسیون نقش runtime کار می‌کنند. سناریوی `PSY-A01` تأیید شده است.

- [x] PSY-1.9 ساخت migration و API پیش‌نویس، انتشار و لغو انتشار بلاگ با slug یکتای Tenant. تزریق محتوای نامعتبر و دسترسی پیش‌نویس را آزمون کن.
- [x] PSY-1.10 ساخت آپلود مستقیم پارس‌پک با staging خصوصی، فایل نهایی ثابت، اعتبارسنجی نوع و حجم، کلاس دسترسی و پاک‌سازی موقت. بازنویسی فایل، فایل نامعتبر و پیوند بین دو Tenant را آزمون کن.
- [x] PSY-1.11 ساخت ویرایشگر امن بلاگ و صفحات فهرست و مطلب، پخش فیلم و صوت و sitemap per Host. پخش و seek و لغو انتشار را آزمون کن.
- [x] PSY-1.12 آماده‌سازی Compose، Caddy، اعتبارنامهٔ جدا، دامنهٔ تأییدشده و CDN دارایی‌های ثابت. پاک‌سازی دوره‌ای دادهٔ ثبت‌نام، بازیابی پشتیبان، عدم کش HTML خصوصی، درگاه و باکت هدف را پیش از پایلوت بررسی کن.
- [x] PSY-1.13 اجرای سناریوهای پایلوت، ثبت رخداد و روش پشتیبانی و پیگیری پرداخت. شواهد واقعی پذیرش و نتیجهٔ هر دو پایلوت را هنگام مجاز بودن انتشار ثبت کن.

- [x] PSY-5.13 اصلاح جست‌وجوی دامنه و عضویت در مسیر واقعی سرور طبق قرارداد lookup محدود، با حفظ RLS و سطح دسترسی `app_user`. هر دو Host تأییدشده باید پروفایل خود را بگیرند، Host ناشناخته `404` بگیرد و مالک فقط تنظیمات مطب دارای عضویت معتبر را بخواند و ذخیره کند. پیش‌نیاز آزمون دیتابیس `PSY-5.12` است.
- [x] PSY-5.14 اصلاح مسیر Outbox از ذخیرهٔ تنظیمات تا Worker. با نقش‌های کم‌اختیار، ثبت تغییر و رویداد را در یک تراکنش نگه دار و دسترسی Worker را به عملیات صف محدود کن. روی PostgreSQL واقعی، ثبت رویداد، بازگشت تراکنش در صورت شکست درج، پردازش رویداد و پاک‌سازی کش فقط برای Host همان مطب را آزمون کن.
- [x] PSY-5.15 اصلاح تنظیمات SSR و پاسخ خطای API. بیلد سایت با `INTERNAL_API_URL` در زمان اجرا باید پروفایل همان Host را دریافت کند. برای Host ناشناخته و در دسترس نبودن API، پاسخ صریح و بدون کش مشترک بده. تست روی بیلد اجرا شود و انتشار اطلاعات نمونه به‌عنوان محتوای مطب را رد کند.
- [x] PSY-5.16 اتصال تنظیمات پنل به مطب فعال و دامنهٔ عمومی تأییدشدهٔ آن. مطب فعال را از نشست و عضویت معتبر تعیین کن. با دو مطب، خواندن و ذخیره، بازشدن پیش‌نمایش روی دامنهٔ درست پیش از ذخیره و نمایش خطای API در فرم را آزمون کن.
- [x] PSY-5.17 اصلاح fallback رجیستری قالب. فقط شناسه‌های ثبت‌شده را انتخاب کن. رندر خانه و پیش‌نمایش برای شناسهٔ ناشناخته، از جمله کلیدهای ارثی شیء، باید با قالب `minimal` و بدون خطای SSR انجام شود.
- [x] PSY-5.18 اصلاح رگرسیون رابط رزرو در موبایل و RTL. در عرض ۳۹۰ پیکسل صفحه بدون اسکرول افقی باشد. فرم رزرو از `Modal` مشترک استفاده کند و نقش دیالوگ، انتقال و بازگشت فوکوس و بستن با Escape آزموده شوند. انتخاب تاریخ شمسی همچنان باید تاریخ میلادی ISO را به API بفرستد.
- [x] PSY-5.19 فعال‌کردن بررسی واقعی `pnpm lint` در پروژه‌های workspace. تأیید کن دستور روی کد معتبر موفق می‌شود و برای یک تخلف عمدی در فایل آزمایشی کد خروج غیرصفر می‌دهد.
- [x] PSY-5.20 اجرای دوبارهٔ `PSY-A12` پس از اصلاحات، روی استک محلی با PostgreSQL، نقش runtime و دو Host. بعد از ذخیره و پردازش Outbox، خانهٔ A باید ظاهر تازه را نشان دهد و B با ظاهر قبلی `HIT` بماند. دو درخواست پیاپی `/preview` باید کش مشترک را دور بزنند. نتیجهٔ رگرسیون صفحات، موبایل و RTL، `make verify-psychology` و `pnpm lint` را در `PROGRESS.md` ثبت کن.

**پایان فاز** — پس از تکمیل اصلاحات، آزمون `PSY-A12` باید تأیید کند که هر مطب می‌تواند ظاهر خودش را پیش‌نمایش و منتشر کند.

## PSY-6 — ظاهر سایت پیش از عرضه

[از اینجا شروع کن و فایل‌های کد را پیدا کن](modules/site-appearance.md#از-اینجا-شروع-کن) · [تصمیم PSY-D10](DECISIONS.md#psy-d10--قالب-و-پالت-مستقل-پیش-از-عرضه) · [پذیرش PSY-A13](ACCEPTANCE.md#psy-a13--انتخاب-و-انتشار-ظاهر-سایت)

برای نمونهٔ محلی از `PSY-5.17` شروع کن و `PSY-6.1` تا `PSY-6.3` را انجام بده. برای یکپارچه‌سازی به پیش‌نیازهای هر زیرتسک مراجعه کن. اجرای نمونهٔ محلی فقط رندر را تأیید می‌کند و معیارهای دسترسی و انتشار در `PSY-6.7` تأیید می‌شوند.

### نمونهٔ محلی ظاهر

- [x] PSY-6.1 کاتالوگ چهار پالت آماده و توکن‌های DaisyUI را اضافه کن. بعد از `PSY-5.17`، رندر SSR پالت پیش‌فرض و یک پالت دیگر را با fixture محلی تأیید کن. تغییر پالت با قالب ثابت و تغییر قالب با پالت ثابت آزمون شوند.
- [x] PSY-6.2 افزودن `Shell` اختیاری به قرارداد فعلی رجیستری و استفاده از آن در `BaseLayout.astro`. خانه، پیش‌نمایش و مسیرهای داخلی از همان چیدمان بدنه استفاده کنند. رگرسیون `minimal` و `clinical` و مالکیت متا در `BaseLayout` را بررسی کن. پیش‌نیاز `PSY-5.17` است.
- [x] PSY-6.3 ساخت نمونهٔ محلی `mobile-app` پس از `PSY-6.2`. چهار مقصد اصلی و منوی «بیشتر» را به ناوبری RTL وصل کن. خانه، جزئیات دوره و فرم رزرو در موبایل آزمون شوند. تأیید نهایی فرم رزرو پس از `PSY-5.18` است.

### تنظیمات، پنل و پذیرش

- [x] PSY-6.4 افزودن migration جدید برای `palette_id` با پیش‌فرض معتبر و تکمیل seed مطب‌های ساختگی. `up/down/up` و `FORCE RLS` را با نقش runtime آزمون کن. پیش‌نیاز fixtureهای دیتابیس `PSY-5.12` است.
- [x] PSY-6.5 تفکیک نوشتن محتوا و ظاهر در `internal/settings` و قرارداد API. پیش‌نیاز این گروه `PSY-6.1`، `PSY-6.3`، `PSY-6.4`، `PSY-5.13` و `PSY-5.14` است. زیرتسک‌ها به‌ترتیب اجرا می‌شوند.
  - [x] PSY-6.5.1 ساخت Queryهای جدا با sqlc برای پروفایل و ظاهر و اتصال به سرویس تراکنشی. ذخیرهٔ هم‌زمان هر دو عملیات و rollback در صورت شکست Outbox را آزمون کن.
  - [x] PSY-6.5.2 اتصال `GET` و `PUT` ظاهر به گارد حساب و عضویت در Go. اعتبارسنجی، CSRF و ایزولاسیون را آزمون کن. تغییر قرارداد نوشتن فرم محتوای موجود با برش `PSY-6.6.2` انجام می‌شود.
  - [x] PSY-6.5.3 افزودن مسیرهای جدید ظاهر و `palette_id` پاسخ عمومی به OpenAPI و کلاینت typed. تطابق شناسه و نسخه در Go، کاتالوگ مشترک و رندر سایت را آزمون کن.
- [x] PSY-6.6 افزودن بخش «ظاهر سایت» به پنل فعلی و اتصال به رندر SSR. پیش‌نیاز این گروه `PSY-6.5`، `PSY-5.15` و `PSY-5.16` است.

- [x] PSY-6.8 پیش از فعال‌سازی کش اشتراکی HTML، پاک‌سازی خانه و صفحات جزئیات Host متأثر را با Worker و آداپتر واقعی CDN تأیید کن. پس از تغییر ظاهر A، کش B باید `HIT` بماند. این تسک به `PSY-6.7` وابسته است و پذیرش عرضهٔ اول با کش HTML خاموش به آن وابسته نیست.

**پایان فاز برای عرضهٔ اول** — حساب مجاز برای مطب‌های دارای عضویت می‌تواند قالب و پالت را جدا انتخاب، پیش‌نمایش و منتشر کند. شواهد `PSY-A13` ثبت شده‌اند. انتشار واقعی طبق روند تأیید محیط هدف انجام می‌شود.
