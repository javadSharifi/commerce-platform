# پلتفرم، دسترسی و محیط اجرا

**تسک‌ها** — `PSY-0`، `PSY-1.12`، `PSY-1.13`، `PSY-2.6` و `PSY-4`. [چک‌لیست](../TASKS.md)

## Tenant و دامنه

- استقرار روان‌شناسی PostgreSQL، migration، اعتبارنامهٔ برنامه، باکت و پشتیبان مستقل خودش را دارد. همهٔ کلینیک‌های همین استقرار روی یک DB و schema با RLS هستند.
- سایت عمومی از Host تأییدشده و پنل از نشست و عضویت، tenant context می‌گیرد. لبهٔ Caddy و API محدودهٔ Hostهای معتبر را اعمال می‌کنند. ورودی `tenant_id` مجوز ایجاد نمی‌کند. RLS حتی برای دامنه و عضویت فعال می‌ماند و bootstrap lookup کم‌اختیار است.
- پیش از عرضه انتخاب زیردامنهٔ پایلوت، تأیید مالکیت دامنهٔ اختصاصی، TLS و جدایی Host در محیط هدف آزموده می‌شود. سایت عمومی فقط لوگو، نام، معرفی، راه تماس عمومی و محتوای منتشرشده را از API می‌گیرد.

## نقش‌ها و نشست‌ها

| نقش | عملیات مجاز |
| --- | --- |
| مالک | تنظیمات، عضویت، دامنه، پذیرندگی، مدیریت محتوا و مشاهده و اصلاح مالی مجاز |
| مدیر محتوا | کارگاه، بلاگ و دوره و رسانهٔ مربوط. گزارش مالی و اطلاعات تماس ثبت‌نام‌ها در این نقش باز نمی‌شود. |
| پذیرش | فهرست ثبت‌نام همان کلینیک و وضعیت تأیید. تقویم و تنظیم و پیگیری نوبت با دسترسی عملیاتی به نام و شماره. |
| درمانگر | تقویم و اطلاعات هماهنگی نوبت‌های خودش در همان کلینیک |
| خریدار | دادهٔ حساب خودش و دسترسی‌های خرید خودش در همان Tenant |
| مهمان | محتوای عمومی، درخواست ثبت‌نام یا نوبت و پیگیری خصوصی همان درخواست در مرورگر آغازکننده |

مالک در صورت نیاز نقش‌های عملیاتی را جداگانه به اعضا می‌دهد. نقش‌ها در هر درخواست از سمت Backend کنترل می‌شوند. حساب پنل و حساب خریدار کوکی و نشست مستقل، انقضا و logout دارند. محدودیت نرخ روی login، بازیابی، ثبت‌نام و نوبت اعمال می‌شود. مقادیر نشست، کد بازیابی و شناسهٔ پیگیری در DB به‌شکل هش و با انقضا یا ابطال مناسب نگه‌داری می‌شوند. ایمیل ورودی شناسهٔ ورود است و مالکیت صندوق ایمیل به‌خودی‌خود مجوز خرید یا انتقال حساب ایجاد نمی‌کند.

## حریم خصوصی و عملیات

- فرم کارگاه و نوبت فقط نام و شمارهٔ تماس می‌گیرند. فیلد آزاد برای علت مراجعه و مسیر فایل درمانی وجود ندارد. پیش از ارسال، متن شفاف هدف استفاده از اطلاعات نمایش داده می‌شود.
- پیش‌فرض پایلوت پاک‌سازی نام و شمارهٔ نوبت و ثبت‌نام رایگان ۹۰ روز بعد از پایان یا لغو است. در ثبت‌نام پولی، اطلاعات تماس پس از ۹۰ روز یا پس از بسته شدن اختلاف مالی، هرکدام دیرتر است، پاک می‌شود. مبلغ، Snapshot، شناسهٔ مرجع و وضعیت مالی طبق سیاست نگه‌داری مالی مصوب محیط هدف جدا می‌مانند. پاک‌سازی و مهلت نگه‌داری پشتیبان پیش از عرضه با شرایط محل اجرا بررسی می‌شوند.
- پاسخ خصوصی، خروجی فهرست و لینک پخش خصوصی `no-store` هستند. لاگ ساختاریافته تنها شناسهٔ عملیاتی و نتیجه دارد. نام، شماره، متن حساس، کد بازیابی و URL امضاشده در لاگ ثبت نمی‌شوند.
- صف داخلی PostgreSQL با Worker همان برنامه پردازش می‌شود. Worker فقط اطلاعات لازم برای یافتن کار را با نقش محدود می‌گیرد و تغییر داده را با Tenant معتبر انجام می‌دهد. بررسی restore، HTTPS، backup، سلامت و دسترسی دو Tenant جزء پذیرش است.
