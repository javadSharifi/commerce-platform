# آزمون پذیرش مسیر روان‌شناسی

برای هر سناریو، نتیجهٔ موفق و خطا، شناسهٔ تسک، محیط و شواهد بدون دادهٔ شخصی را ثبت کن. تست API و دیتابیس با PostgreSQL واقعی و نقش runtime اجرا می‌شود. تست مرورگر با دو Host و دادهٔ ساختگی اجرا می‌شود. نتیجهٔ Sandbox یا Adapter تستی فقط همان محیط را پوشش می‌دهد. [الگوی ایزولاسیون](../patterns/03-tenant-isolation-test.md) · [نقشهٔ راه](TASKS.md)

| شناسه | رفتار قابل مشاهده |
| --- | --- |
| PSY-A01 | A و B روی دو Host فقط دادهٔ خودشان را نمایش می‌دهند. Host نامعتبر خطا می‌گیرد. با ID یا header جعلی، API پنل و عمومی داده یا تغییری در Tenant دیگر ایجاد نمی‌کنند. نقش runtime RLS را دور نمی‌زند. |
| PSY-A02 | مالک کارگاه رایگان و پولی با زمان، مکان و ظرفیت منتشر می‌کند. کاربر مهمان ثبت‌نام را تکمیل و نتیجهٔ خودش را می‌بیند. ظرفیت صفر یا قیمت کلاینت نمی‌تواند ثبت‌نام معتبر ایجاد کند. |
| PSY-A03 | دو درخواست هم‌زمان برای صندلی آخر حداکثر یک رزرو زنده یا ثبت‌نام قطعی ایجاد می‌کنند. رزرو منقضی ظرفیت را آزاد می‌کند. تغییر ظرفیت، لغو و Verify هم‌زمان سقف را نمی‌شکنند. |

| PSY-A05 | پیش‌نویس بلاگ در صفحه، فهرست، sitemap و رسانهٔ عمومی دیده نمی‌شود. مطلب منتشرشده و رسانهٔ معتبر در Host درست دیده می‌شوند. لغو انتشار صدور URL جدید را قطع می‌کند و URL قدیمی پس از TTL منقضی است. |
| PSY-A06 | نمونهٔ تصویر، فیلم و صوت روی باکت هدف آپلود می‌شود و پخش و seek کار می‌کند. فایل ناسازگار، اضافه‌حجم و فایل Tenant دیگر رد می‌شوند. استفادهٔ مجدد از URL موقت فایل منتشرشده را عوض نمی‌کند. |
| PSY-A07 | دو درخواست برای یک سانس فقط یک نگه‌داشت فعال دارند. تأیید و لغو مجوز و زمان را بررسی می‌کنند. جابه‌جایی به سانس پر، نوبت قبلی را از بین نمی‌برد. درمانگر نوبت دیگران را نمی‌بیند و خروجی عمومی فاقد نام و شماره است. |
| PSY-A08 | خریدار پس از Verify یک دسترسی همان دوره می‌گیرد. Retry اثر تکراری ندارد. آرشیو جلوی فروش تازه را می‌گیرد و دسترسی خرید قبلی برقرار می‌ماند. بازپرداخت صدور URL تازه را متوقف می‌کند. |
| PSY-A09 | کاربر مهمان، حساب دیگر و Tenant دیگر نمی‌توانند URL یا فایل خصوصی درس را بگیرند. URL کوتاه‌عمر با دسترسی معتبر تمدید می‌شود. مصرف خارج از سهمیه، URL مستقیم بدون امضا و استفادهٔ دوباره از کد بازیابی رد می‌شوند. |
| PSY-A10 | پیش از عرضه، TLS و جدایی Hostها، ثبت‌نام موبایل، callback در پذیرندگی منتخب، پخش باکت واقعی، عدم کش پاسخ‌های خصوصی و بازیابی پشتیبان تأیید شوند. برنامهٔ پشتیبانی و نتایج دو پایلوت واقعی نسخهٔ ۱ ثبت شوند. |
| PSY-A11 | بعد از فعال شدن کش HTML، ویرایش مقالهٔ A فقط URLهای متأثر همان Host را purge می‌کند و کش B پابرجاست. `no-store` برای پیش‌نویس، پرداخت، وضعیت، نوبت، حساب و پخش خصوصی در مسیر CDN هم مؤثر است. |
| PSY-A12 | مالک Tenant A با دادهٔ واقعی همان مطب `minimal` و `clinical` را در `/preview` مقایسه می‌کند و قالب، رنگ برند، گردی و مقیاس را ذخیره می‌کند. پنل پس از پاسخ موفق `PUT /v1/admin/site` با `private, no-store` ذخیره را بلافاصله تأیید می‌کند. خانهٔ Host A بدون کش HTML در نخستین درخواست پس از ذخیره و با کش HTML پس از پردازش موفق Outbox و پاک‌سازی همان Host، ظاهر تازه را از نخستین رندر بدون FOUC نشان می‌دهد. ظاهر و ورودی کش Host B حفظ می‌شوند. |
| PSY-A13 | حساب مجاز در پنل مطب A قالب و پالت را جدا انتخاب، روی Host A پیش‌نمایش و منتشر می‌کند. در اولین درخواست پس از انتشار با کش HTML خاموش، خانه، جزئیات و رزرو A ظاهر تازه دارند و B ظاهر قبلی را دارد. حساب‌های دیگر ظاهر را تغییر نمی‌دهند. |
| PSY-A14 | بازطراحی Stitch روی مسیرهای عمومی مطب A با داده و پالت همان مطب در SSR رندر می‌شود. رندر و مسیرهای رزرو، آموزش و بلاگ به قراردادهای فعلی پاسخ می‌دهند و مطب B ظاهر و محتوای خودش را دارد. |
| PSY-A15 | شش صفحهٔ Stitch با پالت دقیق و دادهٔ همان مطب در SSR با مرجع مقایسه می‌شوند. داده و رسانهٔ دو Host از هم جدا می‌مانند و اقدام‌های واقعی کار می‌کنند. |

### PSY-A12 — جزئیات آزمون فاز ۵

- **پنل تا سایت:** روی PostgreSQL واقعی با نقش runtime و دو Host مستقل، ذخیرهٔ Tenant A و بازخوانی تنظیماتش را از پنل و API عمومی بررسی کن. در حالت کش فعال، پیش از تغییر هر دو Host را در کش قرار بده. پس از پردازش Outbox، محتوای تازهٔ A و HIT و ظاهر قبلی B را بررسی کن.
- **پیش‌نمایش:** `/preview` همان محتوای عمومی Host را با گزینه‌های معتبر فرم رندر می‌کند. `Cache-Control: private, no-store` و متای `noindex, nofollow` را در پاسخ بررسی کن. با کش HTML فعال، دو درخواست پیاپی پیش‌نمایش باید کش مشترک را دور بزنند. ورودی نامعتبر به مقادیر امن برمی‌گردد، پیش‌نمایش تنظیمات ذخیره‌شده و کش خانه را تغییر نمی‌دهد و درخواست با همان پارامترها به `/` ظاهر منتشرشده را نشان می‌دهد.
- **قالب و رگرسیون:** اگر شناسهٔ ذخیره‌شده در رجیستری پیدا نشود، خانه با `minimal` رندر شود. در مسیر اولیه، RTL و ظاهر نخستین رندر خانه و پیش‌نمایش را در موبایل بررسی کن. پس از مهاجرت بقیهٔ صفحات، نبود JavaScript اضافه در صفحات محتوایی و رفتار تقویم شمسی رزرو در موبایل و RTL را هم تأیید کن.

### PSY-A13 — انتخاب و انتشار ظاهر سایت

برای اجرای تکرارپذیر، A را با `minimal` و `calm-sage` و B را با `clinical` و `warm-sand` آماده کن. حساب مجاز عضو A باشد و برای آزمون نبود عضویت، در B عضویت نداشته باشد. حساب‌های `owner` و `content_manager` عادیِ A هم در fixture حاضر باشند. همهٔ موارد روی دادهٔ آزمایشی اجرا می‌شوند.

| اقدام | نتیجهٔ مورد انتظار |
| --- | --- |
| حساب مجاز ظاهر A را با همان قالب و پالت `ocean-trust` پیش‌نمایش می‌کند. | `/preview` روی Host A رنگ تازه را نشان می‌دهد و `/` روی A همچنان `calm-sage` است. |
| همان حساب با پالت ثابت `ocean-trust`، قالب `mobile-app` را انتخاب و منتشر می‌کند. | پاسخ `200` است. اولین درخواست خانه، جزئیات دوره و رزرو A، `mobile-app` و `ocean-trust` را در SSR نشان می‌دهد. B همچنان `clinical` و `warm-sand` است. |
| حساب مجاز بعد از انتشار، فرم محتوایی بازشده پیش از انتشار را با تلفن تازه ذخیره می‌کند. | تلفن تازه ذخیره می‌شود و قالب و پالت منتشرشده حفظ می‌شوند. |
| یک حساب عادی فرم محتوا را ذخیره می‌کند و جداگانه مسیر ظاهر را صدا می‌زند. | ذخیرهٔ محتوای مجاز موفق است. درخواست ظاهر `403` می‌گیرد و ظاهر ثبت‌شده ثابت می‌ماند. |
| حساب بدون نشست یا حساب مجاز بدون عضویت B به مسیر ظاهر می‌رسد. یک درخواست نوشتن cross-site هم از پراکسی پنل بررسی می‌شود. | بدون نشست `401` و دو حالت دیگر `403` می‌گیرند. ظاهر ثبت‌شده و Outbox مطب هدف ثابت می‌مانند. |
| همان حساب برای A شناسهٔ ثبت‌نشده یا فیلد `template_version` می‌فرستد. | `400` دریافت می‌کند. ظاهر قبلی و نسخهٔ تعیین‌شده در Go ثابت می‌مانند. |

- **دسترسی روی دو Host:** برای A و B دادهٔ ساختگی، دامنهٔ تأییدشده و ظاهر متمایز بساز. با PostgreSQL و `app_user` تأیید کن حساب پیکربندی‌شده با عضویت A می‌تواند ظاهر A را بخواند و منتشر کند. همان حساب بدون عضویت B، حساب‌های `owner` و `content_manager` بدون مجوز اختصاصی و شرایط بدون حساب پیکربندی‌شده، همگی `403` می‌گیرند. دسترسی بدون نشست و نوشتن بدون CSRF معتبر هم رد می‌شوند. تغییر نامعتبر در هیچ مطبی ثبت نمی‌شود.
- **ذخیرهٔ مستقل:** یک فرم محتوایی با مقادیر قبلی باز بگذار، ظاهر تازه را منتشر کن، سپس تلفن یا توضیحات مطب را از فرم محتوایی ذخیره کن. هر دو تغییر باید ثبت شوند. درخواست مستقیم به مسیر محتوایی با فیلدهای ظاهر باید `400` بگیرد. شکست ثبت Outbox باید تغییر ظاهر را برگرداند. شناسهٔ قالب یا پالت ثبت‌نشده `400` می‌گیرد و نسخهٔ ذخیره‌شدهٔ قالب همانی است که Go از کاتالوگ تعیین کرده است.
- **پیش‌نمایش و انتشار:** در فرم ظاهر، با قالب ثابت دو پالت و با پالت ثابت دو قالب را امتحان کن. پیش‌نمایش روی Host تأییدشدهٔ همان مطب با `private, no-store` و `noindex, nofollow` باشد و از sitemap کنار بماند. پیش از انتشار، تنظیمات ثبت‌شده و ظاهر عمومی A ثابت بمانند. صفحهٔ `/` پارامترهای پیش‌نمایش را نادیده بگیرد. پس از ذخیرهٔ موفق، رندر اولیهٔ `/` و یک صفحهٔ جزئیات و `/booking` روی A ترکیب منتشرشده را نشان دهد. ظاهر و دادهٔ B جدا بمانند.
- **پوشش ظاهری:** پیش‌فرض `minimal` و `calm-sage` و رندر امن برای شناسهٔ ناشناخته را بررسی کن. با `mobile-app` روی موبایل RTL، هر شش مقصد از نوار پایین و منوی «بیشتر» در دسترس باشند. بررسی کن که نوار با دکمهٔ ثبت نوبت، فوکوس و تقویم هنگام بازبودن صفحه‌کلید تداخل نداشته باشد. تاریخ انتخابی همچنان به شکل ISO ارسال شود. متن، حالت فوکوس و پیام‌های خطا در پالت‌های عرضه‌شده خوانا باشند.
- **پیش از فعال‌سازی کش HTML:** آزمون `PSY-6.8` را در مسیر واقعی کش اجرا کن. ابتدا خانه و یک صفحهٔ جزئیات A و B را گرم کن. پس از انتشار ظاهر A و پردازش Outbox، هر دو مسیر A باید ظاهر تازه را بگیرند و خروجی B همچنان `HIT` باشد. دو درخواست پیاپی پیش‌نمایش باید کش مشترک را دور بزنند.

### PSY-A14 — بازطراحی سایت عمومی

پس از `PSY-6.7`، با دو Host تأییدشده و دادهٔ ساختگی متفاوت اجرا کن. A قالب جدید را پیش‌نمایش و با حساب مجاز منتشر کند و B یک قالب ثبت‌شدهٔ دیگر داشته باشد. نمونهٔ HTML `PSY-7.0` فقط برای تأیید مسیر بصری است.

| سناریو | نتیجهٔ مورد انتظار |
| --- | --- |
| پیش‌نمایش A، سپس انتشار و بازخوانی مسیرهای عمومی | رندر اولیهٔ خانه، آموزش، بلاگ و رزرو قالب و پالت A را دارد. پیش‌نمایش `private, no-store` و `noindex, nofollow` دارد. نام و دادهٔ B در A دیده نمی‌شوند و انتشار A ظاهر B را عوض نمی‌کند. |
| یک قالب با دو پالت و یک پالت با دو قالب | رنگ‌ها از پالت منتخب می‌آیند. ناوبری، لایه‌بندی و حالت فعال هر قالب در نخستین رندر درست است. |
| مسیر خانه تا دوره، کارگاه و مقاله | CTA مسیر واقعی همان آیتم را باز می‌کند. محتوای بدون تصویر و فهرست خالی خوانا می‌مانند. پیش‌نویس بلاگ نمایش داده نمی‌شود و جزئیات نامعتبر کد وضعیت موجود را می‌دهند. |
| انتخاب درمانگر، تقویم شمسی و سانس در رزرو حضوری | تاریخ در رابط شمسی و درخواست API در قالب ISO است. زمان از سانس API می‌آید. سانس نامعتبر یا پر خطای خوانا می‌دهد و وضعیت موفق از پاسخ واقعی API می‌آید. |
| پیمایش RTL در دسکتاپ و عرض ۳۹۰ پیکسل | یک `h1`، نشانهٔ صفحهٔ فعال، ترتیب منطقی کلید Tab، فوکوس نمایان و امکان بستن مودال با Escape برقرار است. نوارهای ثابت روی فرم و فوکوس نمی‌افتند و اسکرول افقی نداریم. |
| حساب، پیگیری و خروجی SSR | پاسخ‌های خصوصی `no-store` دارند. متا و کدهای وضعیت را `BaseLayout` و مسیرهای موجود تعیین می‌کنند. صفحهٔ محتوایی بدون جاوااسکریپت اولیه خوانا و قابل پیمایش است. |

### PSY-A15 — تطبیق دقیق با Stitch

روی Host آزمایشی A، قالب `editorial` و پالت Stitch را انتخاب کن. مرجع و سایت را با مرورگر و مقیاس یکسان، عرض `۱۴۴۰px`، وزیرمتن بارگذاری‌شده، متن ثابت و همان تصاویر قابل‌استفاده ثبت کن. Host B محتوای متمایز و یک پالت دیگر داشته باشد. نگاشت فایل‌های مرجع در [مشخصات بازطراحی](modules/public-site-redesign.md) آمده است.

| سناریو | نتیجهٔ مورد انتظار |
| --- | --- |
| مقایسهٔ شش اسکرین‌شات مرجع و SSR | ترتیب بخش‌ها، تراز RTL، رنگ، تایپوگرافی، عرض ظرف، فاصلهٔ بخش‌ها، فرم کارت‌ها و برش تصاویر با مرجع منطبق‌اند. اختلاف‌های باقی‌مانده همراه با شواهد و تأیید صاحب پروژه ثبت شده‌اند. |
| پیش‌نمایش و ذخیرهٔ ظاهر A روی همان قالب با دو پالت | رنگ محاسبه‌شدهٔ پس‌زمینه `#FAF9F6`، کارت `#FFFFFF`، سطح گرم `#F3EFE9`، دکمهٔ اصلی `#2D4F43` و تأکید `#C9825B` در پالت Stitch با مرجع برابر است. با انتخاب پالت دیگر، توکن‌های آن در نخستین رندر اعمال می‌شوند. ظاهر B جدا می‌ماند و پیش‌نمایش `private, no-store` است. |
| خانه، آموزش و بلاگ با دادهٔ کامل و بدون داده | کارت‌ها محتوای منتشرشده، رسانه و CTA همان آیتم را نشان می‌دهند. فیلتر آموزش و جست‌وجو و دسته‌بندی بلاگ بر اساس دادهٔ واقعی نتیجه می‌دهند. رکورد بدون تصویر، فهرست خالی و خطای API حالت مشخص دارند. پیش‌نویس و دادهٔ نمونهٔ فرانت‌اند در خروجی عمومی دیده نمی‌شوند. |
| داده و رسانهٔ دو مطب در PostgreSQL با نقش runtime | A داده و رسانهٔ B را نمی‌خواند و تغییر نمی‌دهد. رسانهٔ نامعتبر یا خارج از دسترس رد می‌شود. تغییر محتوای عمومی و ثبت Outbox در یک تراکنش انجام می‌شوند. |
| رزرو حضوری و رگرسیون مسیرها | انتخاب تاریخ شمسی، ارسال تاریخ ISO، سانس معتبر، رد سانس پر و وضعیت پیگیری با API جاری کار می‌کنند. مسیرهای خصوصی `no-store` دارند و فوکوس، پیمایش RTL و حالت‌های خطا طبق `PSY-A14` کار می‌کنند. |

## سنجش قبل از عرضه

- دادهٔ شخصی در URL صفحه، query، sitemap، HTML کش‌شده، لاگ و داشبورد عمومی بررسی شود. لاگ Callback و رسانه با پارامترهای محرمانهٔ حذف‌شده ثبت شود.
- اعتبارنامه‌ها، مقادیر عملیاتی، رویهٔ انتشار و شرایط نگه‌داری داده را در محیط مجاز بررسی کن. مدارک پزشکی یا شرح حال در fixture یا تست زمینه ندارد.
- هر نسخه تست‌های فاز خود و رگرسیون نسخه‌های قبلی را اجرا می‌کند. خرابی بازیابی، نشت بین Tenant یا اختلاف مالی مانع عرضهٔ همان نسخه است.
