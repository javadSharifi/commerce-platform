# سایت‌ساز برای روان‌شناس و کلینیک

هر مطب یا کلینیک سایت فارسی و دامنهٔ خودش را دارد. صاحب سایت کارگاه حضوری و بلاگ را مدیریت می‌کند، در مرحلهٔ بعد نوبت می‌دهد و سپس دورهٔ ضبط‌شده می‌فروشد. این پوشه نقطهٔ شروع مسیر روان‌شناسی است.

| سند | چه چیزی در آن پیدا می‌کنی |
| --- | --- |
| [بریف محصول](PROJECT_BRIEF.md) | مشتری هدف، محدودهٔ نسخه‌ها، معماری و معیار موفقیت |
| [نقشهٔ راه](TASKS.md) | فازها، تسک‌ها، وابستگی‌ها و معیار پایان فاز |
| [نقشهٔ پروژه](PROJECT_MAP.md) | مسیر برنامه‌ریزی‌شدهٔ هر قابلیت، قرارداد و تست |
| [تصمیم‌ها](DECISIONS.md) | قواعد ثبت‌نام، نوبت، پرداخت، رسانه، دسترسی و حریم خصوصی |
| [مدل داده](DATA_MODEL.md) | موجودیت‌ها، رابطه‌ها و قیدهایی که migrationها باید رعایت کنند |
| [مشخصات ماژول‌ها](modules/README.md) | رفتار دقیق هر قابلیت در پنل، سایت و Backend |
| [سناریوهای پذیرش](ACCEPTANCE.md) | آزمون‌های انتشار هر نسخه و بررسی محیط واقعی |
| [وضعیت اجرا](PROGRESS.md) | تسک بعدی، نتیجهٔ تأیید و یادداشت برای جلسهٔ بعد |

## شروع کار برای ایجنت

1. [AGENTS.md](../../AGENTS.md) و [روش کار](../WORKFLOW.md) را بخوان. برای تسک `PSY-*` از فایل‌های همین پوشه استفاده کن.
2. [وضعیت](PROGRESS.md) و [چک‌لیست](TASKS.md) را باز کن، اولین تسک آماده را پیدا کن و سند ماژول و تصمیم‌های همان تسک را بخوان.
3. الگوهای فنی [ماژول tenant-scoped](../patterns/01-tenant-scoped-module.md)، [Migration و RLS](../patterns/02-migration-rls.md) و [تست ایزولاسیون](../patterns/03-tenant-isolation-test.md) مشترک‌اند. قواعد محصول و مسیرهای پیاده‌سازی روان‌شناسی از این پوشه می‌آیند.
4. هر تسک را با سناریوی پذیرش خودش تحویل بده. وضعیت را در [PROGRESS.md](PROGRESS.md) همین پوشه ثبت کن.
